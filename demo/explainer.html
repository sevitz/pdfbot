Every page lands where it should.

pdfbot saves a web page as a PDF from one button, with no print dialog and nothing sent to a server. Each PDF page is a picture of the screen with the page's real words laid over it, so it looks exactly right and you can still search, select and copy the text.

How it works

Five steps happen between the click and the download. Saving the one page invoice demo took 0.2 to 0.6 seconds in Chromium on a Mac.

  1. 1

    The click fetches the engine

    Your page only ever loads the 3 KB loader. The first click adds the 240 KB engine to the page, and every click after reuses it. The link carries the version number, so a new release never runs with an old cached engine.

  2. 2

    Measure the live page

    pdfbot reads where every word sits, line by line, and where every image, table row, form control and card is. It also notes the page breaks the page asks for, from data-pdfbot-break or CSS break-before: page.

    Anything marked data-pdfbot-ignore is hidden while it measures, because it will be missing from the picture too.

  3. 3

    Plan where each page ends

    The page is cut into sheets of paper height. When a cut would slice through a line, a row or a card, it moves up to the gap above, unless that would leave the sheet less than about a third full. Then it cuts straight through instead, rather than waste the paper.

  4. 4

    Draw each sheet as a picture

    html2canvas-pro redraws the page onto a canvas, one sheet at a time, so memory stays flat however long the page is and no browser canvas limit is hit. Each picture is kept as JPEG or as lossless pixels, whichever file is smaller.

  5. 5

    Lay the real words over it, then save

    Each word goes on top of its own picture, in invisible text, stretched to its measured width, so a selection highlights exactly the letters you dragged across. The font is a single empty glyph that stands in for any character, emoji and Japanese included, with a map back to the real characters for search and copy.

    pdfbot writes the PDF file itself, in about 300 lines, and the browser downloads it.

Build it into a page

Four steps, from the smallest change to the most control. Most pages stop after step 2.

  1. 1

    Add the loader

    Copy pdfbot.js and pdfbot-engine.js from the repo's dist/ folder into your site, side by side, and link the loader. Or link it straight from this site while you try it.

  2. 2

    Add a button

    Any element with data-pdfbot becomes a save button, including ones added later. Give it a selector to save only part of the page. While it works, the button is disabled and reads Saving…

  3. 3

    Tidy the page for paper

    Leave out what has no place on paper, start a new sheet where a section should, and keep together what must not split. Cards, rows and lines already stay whole on their own.

  4. 4

    Or drive it from code

    In an app with a bundler, add pdfbot from GitHub and import it when the button is pressed, so its weight only loads then. This is how recaipe's PDF button works.

From JavaScript

pdfbot.save(options)
Builds and downloads. Resolves to the file name and page count.
pdfbot.toBlob(options)
Builds and hands back the PDF, to upload or preview.
pdfbot.button(options)
Returns a ready-made button element.
pdfbot.mount(options)
Adds a floating button to the corner of the page.
pdfbot:start, :progress, :done, :error
Events on document while a save runs.

What it will not do

Better to know before you build it in.

works, with a catchnot supported

  • Text cannot be retyped in a PDF editor.What you see is the picture. Editing a word in Acrobat changes the hidden layer, not the page. Change the web page and save again instead.
  • It saves the width on screen.Saved from a phone, the PDF has the phone layout. Print stylesheets are not applied.
  • Drop caps made with ::first-letter are not drawn.Wrap the letter in a span instead, as the article demo does.
  • Automatic hyphenation is switched off.The hyphens cannot be drawn, so lines may break a little differently from the screen.
  • Columns are sliced across a page break.Two-column text that runs onto a second sheet continues at the top of each column, not in reading order.
  • Typed form values are pictures only.Text inside inputs shows in the PDF but is not in the searchable layer.
  • Images from other sites need CORS.Without the right headers they come out blank.
  • Files run 100 to 350 KB a page.They are pictures. Flat pages of text are the small end.
  • Tested in Chromium and in Apple's PDF engine.Saving from Safari, Firefox and iPhone has not been tried yet.
